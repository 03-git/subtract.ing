key-rotation.txt — signed key succession for subtract.ing

Problem:
  A signing key dies (hardware loss, compromise, planned retirement).
  Every installer who pinned authorized_signers can no longer verify new artifacts.
  Without a signed succession, the chain of trust breaks silently.

Constraint:
  Reflex 2: ssh-keygen -Y already does it. No new format.

Primitive:
  authorized_signers already supports valid-after and valid-before.
  ssh-keygen -Y verify already enforces them.

---

Format (authorized_signers with time bounds):

  hodori@subtract.ing valid-after="20260301" valid-before="20280301" ssh-ed25519 AAAA...current...
  hodori@subtract.ing valid-after="20280201" ssh-ed25519 AAAA...successor...

  Overlap window (20280201–20280301): both keys verify.
  After 20280301: only successor verifies.

---

Transition record (the chain link):

  File: transitions/YYYYMMDD.txt
  Signed by: the outgoing key

  Contents:
    principal: hodori@subtract.ing
    from: SHA256:<outgoing-fingerprint>
    to: SHA256:<successor-fingerprint>
    effective: YYYY-MM-DD
    reason: rotation | compromise | hardware-loss

  Signature: transitions/YYYYMMDD.txt.sig

  Verification:
    ssh-keygen -Y verify -f authorized_signers -I hodori@subtract.ing \
      -n subtract.ing -s transitions/YYYYMMDD.txt.sig < transitions/YYYYMMDD.txt

  The outgoing key attests its own successor. Anyone holding the old
  authorized_signers can verify the transition, then trust the new key.

---

Planned rotation (key is alive):

  1. Generate successor:
     ssh-keygen -t ed25519 -f ~/.ssh/subtract_successor_ed25519

  2. Write transition record, sign with current key:
     ssh-keygen -Y sign -f ~/.ssh/current_ed25519 -n subtract.ing transitions/YYYYMMDD.txt

  3. Add time bounds to authorized_signers:
     - valid-before on current key
     - valid-after on successor key (with overlap)

  4. Sign authorized_signers with current key:
     ssh-keygen -Y sign -f ~/.ssh/current_ed25519 -n subtract.ing authorized_signers

  5. Add transition record + sigs to llms.txt manifest.

  6. Push. Nodes pull new authorized_signers. Old signatures still verify
     during overlap. New artifacts signed with successor after effective date.

---

Emergency recovery (key is lost):

  Problem: the outgoing key cannot sign the transition because it is gone.

  Pre-signed recovery envelope (created while primary key is alive):

    File: recovery/recovery-envelope.txt
    Signed by: the primary key, at time of creation

    Contents:
      principal: hodori@subtract.ing
      recovery-key: SHA256:<recovery-fingerprint>
      created: YYYY-MM-DD
      scope: emergency succession only

    Signature: recovery/recovery-envelope.txt.sig

  The recovery key is generated at the same time as the primary.
  The private half is stored offline (USB in safe, paper backup).
  The envelope is published in the repo — anyone can verify the primary
  key pre-authorized this specific recovery key.

  On key loss:

    1. Retrieve recovery private key from offline storage.

    2. Write transition record, sign with recovery key:
       ssh-keygen -Y sign -f /path/to/recovery_ed25519 -n subtract.ing transitions/YYYYMMDD.txt

    3. Verifiers walk the two-link chain:

       Link 1 — primary authorized the recovery key:
       ssh-keygen -Y verify -f authorized_signers -I hodori@subtract.ing \
         -n subtract.ing -s recovery/recovery-envelope.txt.sig < recovery/recovery-envelope.txt

       Link 2 — recovery key signed the transition:
       (Add recovery key to a temporary signers file with the principal)
       echo "hodori@subtract.ing $(cat /path/to/recovery_ed25519.pub)" > /tmp/recovery-signers
       ssh-keygen -Y verify -f /tmp/recovery-signers -I hodori@subtract.ing \
         -n subtract.ing -s transitions/YYYYMMDD.txt.sig < transitions/YYYYMMDD.txt
       rm /tmp/recovery-signers

    4. Generate new primary, rotate normally from recovery to new primary.

---

Federation (two substrates):

  Each substrate maintains its own authorized_signers and transition chain.
  Cross-substrate trust: substrate A pins substrate B's authorized_signers.
  On rotation: substrate B sends its signed transition record.
  Substrate A verifies the transition against B's old key, then updates its pin.
  No shared keys. No shared authority. Signed artifacts are the handshake.

---

Limitations:

  Post dual-key-loss (primary and recovery both gone):
    - Local artifacts remain signed by the old key
    - Verifiers who already hold the old authorized_signers can still verify them
    - New installers who only have the new authorized_signers cannot verify
      pre-rotation artifacts — the old key is not in their signers file
    - This is identity loss. The chain is terminated, not transferred.
    - Old artifacts are historically valid but not discoverable from the new chain.

---

What this does not do:
  - Revocation lists. Absence is the revocation: valid-before expires the key.
  - Certificate authorities. The signer is the authority. No third party.
  - Key escrow. No one else holds your private key. Ever.
  - Automatic rotation. The human signs. The human decides when.
